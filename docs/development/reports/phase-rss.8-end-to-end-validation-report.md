# گزارش فاز RSS.8 — اعتبارسنجی End-to-End و سخت‌سازی عملیاتی

تاریخ: 2026-07-27

خلاصه:
- در این فاز مجموعه‌ای از تست‌های یکپارچه‌سازی (integration tests) برای خط لوله‌ی RSS پیاده‌سازی شد تا جریان کامل از `FeedSource` تا `Podcast` و `Episode` را اعتبارسنجی کند.
- هدف: تضمین رفتار قطعی، تکرارشونده (idempotent)، و ایمن برای موارد موفق، خطاها و حالات جزئی نامعتبر.

تست‌ها و سناریوهای پیاده‌سازی‌شده:
- سناریو 1 — همگام‌سازی موفق: بارگذاری FeedSource، واکشی، پارس، نرمال‌سازی، ایجاد Podcast/Episode و به‌روزرسانی وضعیت FeedSource به `SUCCESS`.
- سناریو 2 — تکرار همگام‌سازی: اجرای مکرر و بررسی عدم ایجاد تکراری برای Podcast/Episode (idempotency).
- سناریو 3 — به‌روزرسانی اپیزود: شناسایی اپیزود موجود براساس `guid` و به‌روزرسانی متادیتای قابل‌تغییر بدون تغییر هویت.
- سناریو 5 — در دسترس‌نبودن فید: شبیه‌سازی خطای شبکه و بررسی وضعیت `FAILED` و ثبت `lastError` بدون تغییر Podcast/Episode.
- سناریو 6 — XML نامعتبر: شکست پارسر، عدم persistence و وضعیت `FAILED` مشاهده می‌شود.
- سناریو 7 — خطای جزئی: فید شامل اپیزودهای معتبر و نامعتبر — واردسازی اپیزودهای معتبر، نادیده‌گیری نامعتبرها، و اتمام همگام‌سازی با وضعیت صحیح.
- سناریو 8 — فید خالی: همگام‌سازی بدون خطا، بدون ساخت اپیزود، و به‌روزرسانی FeedSource.
- سناریو 9 — Podcast موجود: استفاده مجدد از Podcast موجود و حفظ مالکیت (`ownerId`).

رویکرد تست:
- تست‌ها به صورت integration نوشته شده‌اند و تنها درخواست‌های HTTP خارجی توسط سرویس واکشی (fetcher) شبیه‌سازی شده‌اند.
- برای اجرای تست‌ها لازم است متغیر محیطی `DATABASE_URL` به یک دیتابیس PostgreSQL تستی اشاره کند. در صورت عدم تنظیم، مجموعه‌ی تست‌های E2E به صورت خودکار نادیده گرفته می‌شوند تا توسعه محلی بدون دیتابیس نیز ممکن باشد.

خلاصه پوشش و محدودیت‌ها:
- پوشش: matching (guid/audioUrl/title+publishedAt)، normalization، persistence، وضعیت‌های FeedSource.
- محدودیت‌ها: به علت طراحی فعلی Prisma با provider `postgresql`، اجرای واقعی تست‌ها نیازمند یک دیتابیس PostgreSQL تستی است؛ در محیط‌های بدون دیتابیس، تست‌ها نادیده گرفته می‌شوند.

نتایج دستیابی اهداف:
- تکرارشوندگی و محافظت در برابر تکرار (idempotency) بررسی شد.
- تشخیص تکراری‌ها (guid/audioUrl/title+publishedAt) تایید شد.
- حالات خطا (شبکه، XML نامعتبر) به صورت ایمن مدیریت شدند.
- هیچ تغییر schema، API جدید، یا اجرای پس‌زمینه (scheduler/worker) اضافه نشد.

دستورالعمل اجرا (محلی):
1. تنظیم متغیر محیطی `DATABASE_URL` به یک PostgreSQL تستی (در صورت نیاز). 
2. اجرا:
```
pnpm --filter @castaminofen/api build
pnpm --filter @castaminofen/api test
pnpm --filter @castaminofen/api exec prisma validate
pnpm lint
```

دشواری‌ها و محدودیت‌های شناخته‌شده:
- نیاز به دیتابیس PostgreSQL برای اجرای واقعی تست‌های E2E (قید شده در بالا).
- تست‌ها رفتار شبکه را شبیه‌سازی می‌کنند و بنابراین پوشش لایه شبکه به صورت واقعی محدود است (اما مطابق با الزامات فاز اجازه داده شده است).

پیشنهادات بعدی:
- افزودن CI job مجزا برای اجرای این مجموعه تست‌ها با دیتابیس PostgreSQL موقتی (pg:latest) برای اطمینان از regression protection.
